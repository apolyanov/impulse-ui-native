# Development and release workflows

Run commands from the repository root unless a command says otherwise.

## Environment

- Node.js: 22.21 or newer within Node 22.
- pnpm: 10.19 or newer; the repository records its exact package-manager
  version in the root manifest.
- Install with `pnpm install`.

The workspace uses hoisted node modules, catalog-managed versions, strict
TypeScript, `noUncheckedIndexedAccess`, bundler module resolution, and shared
Prettier import sorting.

## Common checks

```sh
pnpm check-types
pnpm -r typecheck
pnpm lint
pnpm build
```

Target a package during iteration:

```sh
pnpm --filter @impulse-ui-native/<package> typecheck
pnpm --filter @impulse-ui-native/<package> build
pnpm --filter @impulse-ui-native/<package> lint
```

Package lint scripts apply fixes. Inspect the diff afterward. Format changed
TypeScript, TSX, JavaScript, JSON, and Markdown with the relevant package format
script or targeted Prettier. Use `git diff --check` before handoff.

No package-level unit-test runner or test/spec files were present at the review
date. Do not report `typecheck`, lint, builds, or Storybook rendering as unit
tests.

## Storybook and Expo

The host package name is `impulse-ui-native`:

```sh
pnpm --filter impulse-ui-native storybook:web
pnpm --filter impulse-ui-native build-storybook
pnpm --filter impulse-ui-native storybook
pnpm --filter impulse-ui-native storybook:ios
pnpm --filter impulse-ui-native storybook:android
pnpm --filter impulse-ui-native storybook-generate
```

Run `storybook-generate` when native Storybook needs its generated story index
refreshed. Do not hand-edit `.rnstorybook/storybook.requires.ts` when it is
generated by Storybook tooling.

The web Storybook preview installs the full theme/overlay/portal provider tree.
The on-device app root also installs it. When a story behaves differently
between hosts, inspect both preview configurations before changing the
component.

Start the integration playground with:

```sh
pnpm --filter playground start
```

Read `apps/playground/AGENTS.md` first and use the exact Expo-version docs it
requires.

## Site

Read `apps/site/AGENTS.md` before site work; it requires using the installed
Next.js version documentation from `node_modules/next/dist/docs/`.

```sh
pnpm --filter @impulse-ui-native/site dev
pnpm --filter @impulse-ui-native/site check-types
pnpm --filter @impulse-ui-native/site lint
pnpm --filter @impulse-ui-native/site build
```

The site version is imported from the toolkit manifest. Canonical metadata uses
`SITE_URL`; search verification optionally uses `GOOGLE_SITE_VERIFICATION` and
`BING_SITE_VERIFICATION`. Deployment is Docker Compose with Traefik, documented
in the root README.

## Versioning

Changesets manages all publishable `@impulse-ui-native/*` packages as one fixed
version group. Apps and tooling packages are excluded.

For a release-worthy change:

```sh
pnpm changeset
```

- patch: fixes, metadata corrections, internal improvements;
- minor: new components, props, or exported APIs;
- major: breaking public API or behavior.

Prepare versions with `pnpm version-packages`. Publish with `pnpm release`,
which builds before publishing. Never publish merely because a local change is
complete; publishing requires explicit user intent and valid npm authorization.

Package dry run example:

```sh
pnpm --filter @impulse-ui-native/core publish --dry-run --no-git-checks
```

## Commit convention

Use Conventional Commits:

```text
<type>(<scope>): <imperative summary>
```

Prefer package or repo-area scopes. Common types are `feat`, `fix`, `refactor`,
`chore`, `docs`, `test`, `style`, `build`, and `ci`. Keep the summary focused,
imperative, and usually under 72 characters. See `docs/commit-style.mdx` for
examples.
